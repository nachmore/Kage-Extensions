Untrusted by default

Every extension runs in a sandbox.

That includes the ones Kage’s setup installs. An extension can only ask Kage for what its manifest declares, and you see that list before you install it. Code in the sandbox can still talk to web services; those extensions are marked Online.

  • Walled off

    Extension code runs in a sandboxed frame with no direct access to Kage, your files or your other extensions.

  • Declared up front

    Each card lists what an extension can ask Kage for, in the same words Kage uses when you install it.

  • Held back on update

    An update can’t give itself more access than you approved.

  • Checked in the open

    Changes arrive as public pull requests, and CI checks each extension’s calls to Kage against the access it declares.

Build your own

Cook up an extension.

An extension is a folder: a manifest and a few ES modules, no build step. If you can write a little JavaScript, you can teach Kage something new.

  1. 1

    Start from hello-world

    Copy extensions/hello-world: a manifest, a search provider, a settings page and tests.

  2. 2

    Learn what it can do

    Kage’s extension guide covers launcher results, widgets, agent tools, settings and the sandbox.

  3. 3

    Check it and send it

    npm run check:all and npm test run the same checks as CI. Open a pull request; once it’s merged, it’s in the store.
